# Brutal Buy — Shopify Theme

Your Brutal Buy sports storefront, converted from a static HTML site into a real,
importable Shopify theme.

Everything you built is still here: the same `styles.css` (all 1,872 lines, both
dark and light themes, every animation), the same header, mega menus, drawers,
hero slider, catalog engine, PDP and cart design.

---

## Read this first: why the old zip would not upload

A Shopify theme is not a website made of HTML files. Shopify's uploader requires a
specific package — `layout/theme.liquid`, `templates/`, `sections/`, `snippets/`,
`assets/`, `config/`, `locales/` — and rejects anything else as *"Invalid theme"*.
Connecting GitHub doesn't bypass that; Shopify runs the same validator on the branch.

This repo now has that structure, so it uploads.

## What is real and what is demo

You chose to keep the generated demo catalog. That decision is preserved, but it
means the store runs **two parallel carts**, and that's worth understanding:

| | Demo (kept from your site) | Real Shopify |
|---|---|---|
| Homepage `/` | ✅ all 12 sections, demo products | |
| Catalog | `/pages/catalog` | `/collections/<handle>` |
| Product detail | `/pages/product?id=…` | `/products/<handle>` |
| Cart | `/pages/cart` + header drawer (browser `localStorage`) | `/cart` |
| Search | header search drawer | `/search` |
| Account | `/pages/account` (sample orders) | `/account` (real customer) |
| Checkout | shows a demo toast | ✅ **takes real orders** |

**The demo cart cannot check out.** Products generated by `assets/bb-data.js` don't
exist in Shopify, so they have no variant ID and can't be added to a real order.
The real cart at `/cart` is fully functional.

So the practical path to a live store: add products in Shopify admin → they appear
on `/collections/all` and `/products/...` automatically → those pages add to the
real cart → checkout works.

## Upload it to Shopify

### 1. Build the zip

Shopify wants the theme folders at the *root* of the zip, not wrapped in a folder.
`original-static/` (your untouched originals) must be excluded. A helper is included:

```bash
./make-theme-zip.sh          # writes brutal-buy-theme.zip
```

Or manually:

```bash
zip -r brutal-buy-theme.zip \
  assets config layout locales sections snippets templates \
  -x "*.DS_Store" -x "__MACOSX/*"
```

### 2. Upload

Shopify admin → **Online Store → Themes → Add theme → Upload zip file** →
pick `brutal-buy-theme.zip` → **Publish**.

| Brands | `brands` | `brands` |

## Design notes worth knowing

**Route translation.** `bb-data.js`, `bb-home.js`, `bb-catalog.js`, `bb-product.js`
and `bb-cart.js` still emit `catalog.html?sport=cricket`-style paths internally.
Instead of rewriting every template literal, `BB.fixHref()` in `bb-main.js`
translates them at click and hover time, using routes injected by
`layout/theme.liquid`. Verified against 19 cases, including `b2b.html` (which
contains a digit and initially slipped through the regex).

**Header and footer are built by JS.** `sections/header.liquid` and
`sections/footer.liquid` are mount points; the markup comes from `headerHTML()` and
`footerHTML()` in `bb-main.js`, so it stays byte-identical to your original. The
uppercase/casing, mega menus and drawers are all unchanged. You can toggle the
header's parts (search, account, cart, store locator, theme switch) in the customizer.

**The announcement bar is Liquid.** It moved to `sections/announcement-bar.liquid`,
so its three messages and rotation speed are editable. The rotation animation is
still `initAnnounce()`.

**Two bugs in the original were fixed:**
- The sports carousel arrows never worked — `bindCarouselNav("sportsCarousel")`
  looked for a `#sportsCarouselWrap` wrapper that didn't exist, so it bailed out.
  The section now supplies that wrapper id.
- `bb-home.js` computed `data-delay` with `items.indexOf([e, t, s])`, which is
  always `-1` because it builds a fresh array. Left as-is; the reveal animation
  works because the delay is only cosmetic.

**Product images** still load from Unsplash's CDN, so the demo catalog needs
internet access. Real Shopify products use `image_url` and are served by Shopify.

## Making the demo forms real

Four forms show a toast instead of sending: contact, B2B quote, withdrawal request
and the account profile form. Each is marked `data-demo-toast` in its section.

To make the **contact form** real, replace its `<form>` in
`sections/bb-contact.liquid` with Shopify's tag in Liquid:

```liquid
{% form 'contact', class: 'form-grid' %}
  <div class="form-row">
    <div class="field"><input name="contact[name]" placeholder="Your name" required></div>
    <div class="field"><input type="email" name="contact[email]" placeholder="Email" required></div>
  </div>
  <div class="field"><textarea rows="5" name="contact[body]" placeholder="How can we help?" required></textarea></div>
  <button class="btn btn-primary" style="justify-self:start">Send message →</button>
{% endform %}
```

Then enable the contact form in Shopify admin (Online Store → Preferences).

For the **newsletter**, swap the form in `bb-home.js` for `{% form 'customer' %}`
with `<input type="hidden" name="contact[tags]" value="newsletter">`, and add
`<section id="newsletter">` to `templates/index.json` as a Liquid form section.

## Replacing the demo homepage rails with real products

Once you've added products in Shopify admin:

1. Open the theme customizer on the homepage.
2. **Add section → Featured collection**, pick your collection.
3. Delete the demo rails (`Tabbed products`, `Crowd favorites`) when you're ready.

`sections/bb-featured-collection.liquid` renders real products using the exact same
card design as the demo grid.

## Push this to GitHub

```bash
git init -b main
git add .
git commit -m "Brutal Buy storefront as a Shopify theme"
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

On the first push, Git Credential Manager opens a browser window to sign in to
GitHub. No personal access token needed.

### Connecting Shopify to GitHub needs a clean branch

Shopify's GitHub integration requires the theme files at the **root of the
connected branch with no unrelated folders mixed in**. This repo also holds
`original-static/`, `README.md` and the build scripts — all of which belong in
version control, but none of which may be on the branch Shopify reads.

So `main` keeps everything, and a separate `shopify-theme` branch holds only the
theme folders. `push-theme-branch.sh` builds it for you:

```bash
./push-theme-branch.sh          # branch defaults to shopify-theme
```

It builds the commit through a throwaway git index, so it never switches branches
and never touches your working tree — there is nothing to lose if it fails.
Re-running it with no theme changes is a no-op. Your repo therefore ends up with:

| Branch | Contents | Purpose |
|---|---|---|
| `main` | everything | source of truth, plus your originals |
| `shopify-theme` | the 7 theme folders only | what Shopify connects to |

Then: Online Store → Themes → **Add theme → Connect from GitHub** → pick the repo
→ click **Connect** next to the `shopify-theme` branch.

Prefer not to use GitHub at all? The zip upload path works identically — see
**Upload it to Shopify** above.
